# 插件平台是怎么运作的

这篇讲平台内部的实现原理，不是写插件必须看的东西，照着 `student_manual.md` 的步骤做就能完成作业，不用看这篇。想搞清楚这套机制到底怎么跑起来的，再看。Python 版和 C 版原理不一样，分开讲。

## 要解决的问题

每次实验都要往平台里加一个新算法，而且不能每加一个就去改平台的核心代码，核心代码和算法代码得是两件事。这就是插件化：核心程序只认一个统一的接口（Python 是 `Plugin` 类，C 是 `PluginInfo` 结构体），具体是哪个算法、怎么实现，它完全不关心。

接下来讲 Python 和 C 各自怎么做到"新增一个文件，核心代码一行都不用改"。

## Python 版：运行时扫描 + 动态导入

`main.py` 里的 `load_plugins()` 对 `plugins/` 下的每个子文件夹做三件事。

先找文件：用 `Path.iterdir()` 遍历 `plugins/` 下每个子目录，看里面有没有 `plugin.py`。

找到了就把它当模块导入。正常的 `import` 语句要求模块名写死在代码里，没法用在"不知道有多少个、叫什么名字"的场景。这里用 `importlib.util.spec_from_file_location` 配合 `module_from_spec`、`exec_module`，效果相当于把这个 `.py` 文件当场读进来执行一遍，模块名是运行时拼出来的字符串（`plugin_<目录名>`），不需要提前知道。

模块跑完之后，把类找出来：用 `inspect.getmembers(module, inspect.isclass)` 拿到这个模块定义的所有类，筛出"继承了 `Plugin`、但不是 `Plugin` 本身"的那些，实例化，塞进一个列表返回。

这三步对插件文件有两条硬要求：文件名必须叫 `plugin.py`（第一步按这个名字找），里面至少得有一个继承 `Plugin` 的类（第三步按这条筛）。满足这两点，`category`、`name` 叫什么、`run()` 里写了什么，平台一概不管，它认的是"这是不是一个 `Plugin`"，不认"这个 `Plugin` 具体是什么算法"。

新增插件不用改 `main.py`，是因为 `iterdir()` 每次启动都重新扫一遍磁盘上实际有什么文件夹，而不是读一份写死的名单。

## C 版：编译时静态注册

C 没有运行时 `import` 这种东西。`plugins/` 下的每个 `.c` 文件是在编译阶段就和核心代码一起变成同一个可执行文件的（见 `Makefile` 里的 `$(wildcard plugins/*/*.c)`，新增目录后这一行自动把新文件纳入编译列表，不用手动改）。

但这样一来，编译进同一个可执行文件之后，程序怎么知道这里有几个插件、分别是谁？`main()` 里没有一行代码调用任何具体的插件文件，核心代码压根不知道它们存在。

答案是每个插件文件自己主动举手报到，靠这段代码：

```c
static void __attribute__((constructor)) register_self(void) {
    plugin_register(&info);
}
```

`__attribute__((constructor))` 是 GCC/Clang 的一个特殊标记，意思是这个函数不需要任何人调用，程序一启动、`main()` 还没开始跑之前，运行时会自动执行它。所以即使 `main.c` 完全没提到某个插件文件，只要它被编译进了最终的可执行文件，它的 `register_self` 就会在 `main()` 跑之前自动执行一次，把自己的 `PluginInfo` 塞进 `plugin_registry.c` 维护的那个全局数组。等 `main()` 真正开始跑、调用 `menu_ui_run()` 的时候，所有插件早就注册完了。

很多 C 程序是用 `dlopen`/`dlsym` 在运行时动态加载 `.so` 文件的，好处是不用重新编译核心程序就能换插件，代价是要维护一套 ABI 版本兼容机制，新增字段得考虑旧插件会不会崩，Windows 下还没有 `dlopen` 这个函数，得额外写一层兼容代码。这门课的代码量小，重新编译几秒钟的事，不碰 ABI、不管 Windows 兼容划算得多。所以 C 版用的是编译时静态注册。

## 两个版本的共同点：接口即契约

不管哪个版本，核心代码（`app.py`/`menu_ui.c`）真正依赖的只有几个固定字段：`name`、`category`、`description`，加上"能被调用来执行"（Python 是 `run(text, vis)` 方法，C 是 `run` 函数指针）。别的一概不管，不知道也不关心插件内部在干什么。接口就是双方的约定：一边照约定读信息、调用，一边照约定实现，谁都不用知道对方怎么写的。
