# 数据结构实验课程设计

## 设计原则

1. **统一载体，逐课累积**：每次实验产出一个插件，学生的“成果”不是散落的 `.py`/`.c` 文件，而是可以在同一平台里点开运行的功能列表。到 E5 结束，每个学生手上都有一个装了 8~10 个插件的平台，这本身就是可展示、可复用的作品。
2. **90 分钟课堂讲什么**：课堂时间不用于讲解语法，而是讲三件事——（a）本次算法的核心难点与易错点，（b）如何把算法包装成插件接口，（c）现场跑通一个比课后作业更简单的最小示例。语法与 API 细节留给操作手册自学。
3. **课后任务边界（2 小时）**：除 E6.1 外，课后任务只要求实现"教材标准算法 + 插件封装"，不引入课堂未讲过的新数据结构、不要求性能优化、不要求异常体系设计。工作量对齐"一个中等难度算法的独立实现 + 20 分钟集成"。
4. **明确的验收标准**：每次任务给出可直接判定的输出格式或测试用例，避免学生因为"不知道做到什么程度算完成"而超时。

## 实验一：插件式开发基础（E1.1–E1.3）

**课堂 90 分钟**
- 15 min：为什么要用插件架构做课程作业（对比"每次都重写 main 函数"的痛点）。
- 25 min：讲解 `Plugin` 接口（Python）与 `PluginInfo` ABI（C）的字段含义，现场对照 `plugins/example_recursion` 逐行走读。
- 20 min：现场演示如何新增一个插件目录、注册、在 UI 里跑起来（用比汉诺塔更简单的"斐波那契数列"作为课堂示例，不布置为作业，避免与课后任务重复）。
- 20 min：分发平台代码，学生在自己机器上跑通示例插件（环境搭建、编译工具链验证）。
- 10 min：Q&A、答疑常见环境问题（Python 版本、gcc/make 是否可用）。

**课后任务（≤2 小时）**
- E1.1/E1.2：不单独交付，视为环境搭建与代码阅读，验收方式为课堂或次课开始时抽查（能否成功编译运行平台 + 示例插件）。
- E1.3：任选 Python 或 C 版本，实现**任意一个递归算法**（阶乘、Fibonacci、快速幂三选一，不可选汉诺塔——已作为示例给出），封装为插件并集成到平台。
  - 验收标准：UI 中新增一个分类为 `E1.3 递归算法` 的插件条目；输入合法参数能给出正确结果；输入非法参数（如负数）不崩溃平台。

## 实验二：线性表、栈、队列（E2.1–E2.2）

**课堂 90 分钟**
- 20 min：顺序表 vs 链表的复杂度对比表（插入/删除/随机访问），强调"何时选哪种"而非纯背诵。
- 20 min：栈、队列的应用场景各举一例（表达式求值 / 广度优先遍历前置铺垫），说明这是后续实验（E4 图遍历）会复用的基础设施。
- 30 min：现场用顺序表实现一个"括号匹配校验"作为课堂示例（比课后任务简单）。
- 20 min：插件封装演练——本次插件的 `run()` 如何设计输入参数（例如以逗号分隔的整数序列作为字符串输入）。

**课后任务（≤2 小时）**
- E2.1：实现顺序表和链表各一个，功能覆盖增/删/查/遍历，通过插件提供"输入一串操作指令，输出每步后的表内容"的交互方式。
- E2.2：基于 E2.1 的顺序表或链表实现栈和队列（要求复用底层结构，而非重新造轮子），并实现一个应用示例二选一：
  - 中缀表达式转后缀并求值（栈）
  - 层序遍历模拟输入队列（队列）
- 验收标准：给定 3 组预设测试输入（含边界：空表、单元素、操作序列较长），输出与教材算法结果一致。

---

## 实验三：字符串匹配、矩阵操作（E3.1–E3.2）

**课堂 90 分钟**
- 25 min：朴素匹配的 O(nm) 问题引出 KMP，重点讲 next/fail 数组的构造直觉（画图，不推公式）。
- 20 min：矩阵操作的应用背景——**结合专业方向**，用遥感领域的例子引入：矩阵转置/乘法对应影像波段运算、卷积核处理的雏形，为 E6.1 埋伏笔。
- 25 min：现场手推一个短字符串（长度 ≤ 8）的 next 数组，全班核对。
- 20 min：插件封装注意点——大规模输入（长字符串/大矩阵）时 UI 输出如何截断显示，避免文本框卡死。

**课后任务（≤2 小时）**
- E3.1：实现 KMP 算法，插件输入为（主串, 模式串），输出所有匹配起始位置及 next 数组。
- E3.2：实现矩阵加法、转置、乘法三个基本操作，封装为一个插件（通过参数选择操作类型）。
- 验收标准：KMP 在至少一组含重复前缀的模式串（如 `"ababab"`）上验证正确；矩阵乘法验证维度不匹配时给出友好错误而非崩溃。

## 实验四：二叉树、图（E4.1 ×2）

**课堂 90 分钟**
- 20 min：二叉树的三种遍历 + 层序遍历，强调递归与显式栈两种实现方式的取舍。
- 20 min：图的两种存储方式（邻接矩阵 vs 邻接表）及适用场景，结合遥感场景类比（邻接表更适合稀疏的路网/河网拓扑）。
- 30 min：现场演示用邻接表实现 DFS，全班跟做一个 6 节点小图。
- 20 min：讨论插件如何接收"树/图结构"这种非标量输入（约定一种文本表示法，如括号表示法或边列表）。

**课后任务（≤2 小时）**
- E4.1a：实现二叉树的构建（约定输入格式，如带空节点占位的层序序列）与前/中/后/层序四种遍历。
- E4.1b：实现图的邻接表存储 + DFS 与 BFS 遍历，输入为边列表。
- 验收标准：给定标准测试树/图（提供在操作手册附录），四种遍历序列与 DFS/BFS 序列均正确。

---

## 实验五：查找、排序（E5.1–E5.2）

**课堂 90 分钟**
- 20 min：顺序查找、二分查找、（可选）二叉查找树查找的复杂度对比。
- 25 min：排序算法谱系图——比较类（冒泡/插入/选择/快排/归并）vs 非比较类（计数排序简介），强调快排/归并是重点掌握对象。
- 25 min：现场对比同一组数据在不同排序算法下的比较次数（用平台已有插件跑一遍，直观感受 O(n²) vs O(n log n)）。
- 20 min：插件设计讨论——如何在插件输出中附带"关键操作计数"（比较次数、交换次数），为后续算法分析习惯打基础。

**课后任务（≤2 小时）**
- E5.1：实现二分查找（要求数组有序）+ 顺序查找，插件同时输出两者的比较次数对比。
- E5.2：实现快速排序与归并排序（二选一精做，另一个可选实现），插件输出排序过程关键步骤（如每轮 pivot 选择或每次归并区间）。
- 验收标准：功能正确性通过随机数组测试；排序结果与 Python `sorted()` / 标准库 `qsort` 对比一致。

## 分组实验：专业应用场景（E6.1）

与前 5 次不同，**不设 2 小时上限**，按周分阶段推进（建议跨度 2~3 周，穿插在正常课表中检查进度）。

**课堂角色**：教师从"讲算法"转为"评审设计"。建议拆成两次课：
- 第一次（选题与设计）：每组用 10 分钟提案"要解决什么遥感/地理场景问题，用到哪些已学数据结构"，教师现场点评可行性，防止选题过大（例如不要一上来做完整的空间索引系统，可以做"基于四叉树的栅格影像分块检索"这种可在 1~2 周内做完的切片）。
- 第二次（中期检查）：检查数据结构选型与核心算法是否已跑通最小样例，未跑通的组现场诊断问题。

**任务要求**：
- 必须复用至少 2 种前 5 次实验中实现的数据结构/算法（例如：四叉树 + KMP 用于影像元数据检索；图 + BFS 用于河网连通性分析；矩阵操作 + 排序用于波段统计与阈值分割）。
- 最终以插件形式集成到平台，插件分类统一命名为 `E6 专业应用`。
- 提交物：插件代码 + 一页设计说明（问题定义、数据结构选型理由、复杂度分析）。

**分组平台展示**：每组 8 分钟演示 + 4 分钟提问，评分维度建议：问题的专业相关性（30%）、数据结构运用的合理性（30%）、实现完整性与鲁棒性（20%）、展示表达（20%）。

---

## 评分建议（贯穿 E1–E5）

| 维度 | 占比 | 说明 |
|---|---|---|
| 算法正确性 | 50% | 用标准测试用例验证 |
| 插件集成规范性 | 20% | 是否遵循接口规范、异常是否会导致平台崩溃 |
| 代码质量 | 15% | 命名、复杂度控制、无明显冗余 |
| 手册/注释可读性 | 15% | 能否让助教在 5 分钟内看懂并跑起来 |

这套权重把"集成规范性"独立计分，是刻意的：插件化的价值就在于统一接口，如果学生的插件破坏了平台的健壮性（如异常导致整个 UI 崩溃），要在分数上明确体现。
