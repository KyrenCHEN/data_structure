数据结构实验插件平台使用指南

每次实验写的算法都封装成一个插件，运行在同一个平台上，不是一次性脚本。 这份文档说明平台怎么搭起来的、怎么跑起来、怎么写自己的第一个插件。

一、平台是怎么拼起来的

核心程序只负责发现插件、渲染界面，不认识任何具体算法。插件通过统一接口挂进去： Python 版启动时扫描 plugins/ 目录；C 版编译时把 plugins/ 下所有插件和核心代码一起编译进同一个可执行文件，没有动态库、没有运行时加载。

核心部分（加载/注册、界面）由平台提供，学生不需要改；插件目录由学生各自新增，互不干扰。

二、界面长什么样

同一次课的插件放进同一个菜单。点开一个插件后，左侧出现说明和输入框， 中间上方是可视化画布，下方是文字输出框。

三、跑起来

不熟悉命令行用 VSCode 打开对应文件夹，Python 版点右上角的运行按钮，C 版按 F5， 效果和下面的命令一样，详见 docs/vscode_setup.md。

Python 版

cd platform-python
python3 main.py

只依赖标准库 tkinter，不需要 pip install。

C 版

cd platform-c
make run

插件和核心代码一起编译成一个可执行文件，新增插件后重新 make run 一次就行，Windows 装 MinGW-w64 即可，不需要 WSL。

四、写第一个插件

以 Python 版为例，C 版流程一样，只是把类换成导出函数。

1. 复制模板

复制 template/ 整个目录到 plugins/ 下，改个名字，建议带上算法名和学号后四位。

# template/ 复制为：
plugins/binsearch_1234/
  plugin.py

2. 继承 Plugin，写清楚输入格式

平台不解析输入，description 里写一句话说明格式，example_input() 给一个示例。

from plugin_base import Plugin

class BinarySearchPlugin(Plugin):
    name = "二分查找"
    category = "E5"
    description = "两行文本：第一行有序数组（逗号分隔），第二行要查找的值"

    def example_input(self):
        return "1,3,5,7,9,11\n7"

4. 重新启动平台

重新运行 main.py 会自动扫描 plugins/，不需要改任何核心文件，顶部菜单栏里会出现新插件分类。C 版同理，重新 make run 即可，新插件编译时自动注册。

5. 用边界用例自测

至少验证一组正常输入和一组边界输入，比如空串、模式串比主串长，确认异常不会让平台崩溃。

五、五次实验的安排

每次实验对应平台里新增的一个插件、一个新菜单项，课后任务固定 2~3 个算法，都写进同一个插件里（输入第一行写算法名区分分支），不设选做。第一次课把环境搭建并入实验一，内容刻意放轻。

实验课堂讲什么课后要写的算法（固定，不选做）
E1 环境搭建 + 顺序表插件接口讲解，对照示例逐行走读顺序表插入 + 顺序表删除
E2 栈和队列典型应用场景、现场写括号匹配栈（括号匹配）+ 循环队列
E3 树递归定义、三种遍历的写法规律二叉树四种遍历 + 二叉查找树插入/查找
E4 图邻接矩阵 vs 邻接表、现场写 DFS图的邻接表存储 + DFS/BFS
E5 查找与排序查找/排序谱系，对比不同排序的比较次数顺序/二分查找 + 选择排序 + 快速排序

六、常见问题

插件没有出现在菜单里怎么办？

Python 版检查文件名是否严格为 plugin.py、类是否直接继承 Plugin；C 版先看 make 是否报编译错误，再检查插件文件里有没有漏写 __attribute__((constructor)) 那个注册函数。

怎么表示数组、矩阵、树、图这类输入？

全部用纯文本表示，平台不强制格式，每次实验的任务说明会给出建议格式，全班统一格式，便于批量验收。

C 版为什么是文本菜单，不是图形界面？

C 原生做图形界面需要额外的 GUI 库，会把重心从数据结构挪到界面编程上。文本菜单同样能体现"插件独立编写、统一接口接入平台"这个核心概念，在 Windows/Linux/macOS 上零依赖运行。

提交时要交哪些文件？

只提交 plugins/<你的目录>/，不要提交没改过的核心文件。

完整接口规范与提交要求见仓库 docs/student_manual.md；课程逐次教案见 docs/course_design.md。
