01

平台是怎么拼起来的

两个版本共享同一套心智模型：核心程序只负责「发现插件、渲染界面」， 从不认识某个具体算法；你的插件通过统一接口挂进去，核心程序在运行时才知道它的存在。

核心（加载器 + 注册表 + UI）由平台提供，学生禁止修改 插件目录由学生新增，互不干扰
02

Python 版界面长什么样

同一次课的插件放进同一个菜单；点开一个插件后，左侧出现说明和输入框； 中间是一个大大的纯文本输出框——不管算法多复杂，界面永远只有"一段文本进、一段文本出"。

顶部菜单：一次课一个菜单，同一分类的插件排在一起 左侧面板出现在"点开某个插件"之后；中间输出框只显示纯文本

编写你的第一个插件

以 Python 版为例，五步做完；C 版流程完全一致，只是把类换成导出函数。

1

新建插件目录

在 plugins/ 下新建一个目录，命名建议带上算法名和学号后四位，避免和同学重名。

plugins/kmp_1234/
  plugin.py
2

继承 Plugin，写清楚输入格式

平台不解析你的输入——description 里用一句话说明格式，example_input() 给一个示例，方便自己和助教一键测试。

from core.plugin_base import Plugin

class KmpPlugin(Plugin):
    name = "KMP 字符串匹配"
    category = "E3"
    description = "两行文本：第一行主串，第二行模式串"

    def example_input(self):
        return "ababcabcabababd\nabab"
3

实现 run(text)，返回字符串

text 是输入框里的全部内容，自己按约定的格式解析；不要用 print()，界面只展示 return 的内容。

4

重新启动平台

加载器会自动扫描 plugins/，无需修改任何核心文件，顶部菜单栏里会出现你的插件分类。

python3 main.py
# 顶部出现菜单「E3」→ 里面有「KMP 字符串匹配」
5

用边界用例自测

至少验证一组正常输入和一组边界输入（空串、模式串比主串长等），确认异常不会导致平台崩溃。可以把测试数据存成 .txt，用"加载文本文件"反复读入。

06

常见问题

插件没有出现在菜单里怎么办？

Python 版检查文件名是否严格为 plugin.py、类是否直接继承 Plugin；C 版先看 make 是否报编译错误，再看运行时 [plugin_manager] 的报错信息。

怎么表示数组、矩阵、树、图这类非标量输入？

全部用纯文本表示，平台不强制具体格式，每次实验的任务说明会给出建议格式（如矩阵每行一行、数字间用逗号分隔；树用带占位符的层序序列），全班统一格式，便于用同一份 .txt 批量验收。

C 版为什么是文本菜单，不是图形界面？

刻意的取舍：C 原生做图形界面需要额外的 GUI 库，会把课程重心从数据结构挪到界面编程上。文本菜单同样能验证「插件动态加载」这个核心概念，且在任意 Linux/macOS 环境零依赖运行。

提交时要交哪些文件？

只提交 plugins/<你的目录>/，不要提交未修改过的核心文件（core/、ui/、src/ 等）。

完整接口规范与提交要求见仓库 docs/student_manual.md；课程逐次教案见 docs/course_design.md。
